# ATAS AI 复盘工作台 v0.1 设计草案

日期：2026-11-09。状态：用户已确认采用路线 A，进入实施。

## 目标与已有基础

在已经运行的 macOS 只读 AI Bridge 上，增加用户自己操作的分析产品：模型服务配置、
交易系统和学习目标、可编辑且留存版本的 Prompt、按需分析与报告历史。
用户不需要逐笔填写开仓理由；没有系统档案时也可做描述性分析。

当前基础是 fork 的 `codex/macos-support` 分支、`c095f8c`，插件版本 `0.3.0-macos.2`。
行情查询已在 ATAS X 8.0.15.663 的 BTC Crypto Sim 图表验收。
手动交易日志由独立的 BTC Orderflow Lab 提供，不属于行情桥的数据。

## 界面路线与建议

| 路线 | 体验 | 主要取舍 |
| --- | --- | --- |
| A：ATAS 图表入口 + 本机网页工作台（建议） | 在图表点击“AI 复盘”，打开只在本机运行的中文工作台 | 能承载长报告、设置和规则版本；需要一个本机后台，不是全部画在 ATAS 内 |
| B：全部界面绘制在 ATAS 内 | 聊天和设置都留在平台中 | 当前扩展接口主要提供绘制与输入；长文本编辑、滚动、输入法及密钥输入需要额外验证 |
| C：独立 macOS 桌面应用 | 独立原生窗口，读取现有桥 | 还需要单独的应用安装、打包和签名；首版维护范围更大 |

建议先做 A，保留已运行的 ATAS 指标作为数据和入口组件。
不把内部 Avalonia DLL 的存在当成公开、稳定的插件窗口接口。
官方模块文档与 API 版本标记有差异，因此不要求升级 ATAS，也不依赖本机尚未确认的 PlatformModule。

## 第一版用户流程

1. 从图表“AI 复盘”入口或安装后的本机启动器打开工作台。
2. 首页显示桥版本、标的、模拟账户状态、最近数据时间和日志连接状态。
3. 在“模型服务”填写完整 Base URL、模型名和自己的 Key。连接测试仅发送固定的非交易测试文本。
4. 在“我的系统”填写周期、入场与退出规则、风险规则、练习目标；均可留空。
5. 从“当前行情”或可用的“交易日志”选择分析范围，先生成发送预览。
6. 预览显示目标服务、模型、数据范围、摘要大小和缺失项；点击“开始分析”后才发给模型。
7. 查看报告，针对同一证据继续提问；报告列出所用规则／Prompt 版本及数据获取时间。
8. 可以手动修改系统／Prompt；AI 修改建议显示为提案，用户接受后创建新版本。

工作台采用四个主要页面：分析、交易日志、我的系统、模型设置。
报告历史与当前对话放在分析页面，不另建复杂项目管理或团队功能。

## 第一版实现范围

### 入口和后台

- 复用现有 C# 指标，在状态条附近增加明确的“AI 复盘”入口。
- Python companion 与现有 fork 同仓维护，不要求用户安装 Node 或启动开发服务器。
- 首次安装时配置 Python 虚拟环境及本机启动器；日常点击入口即可启动／复用一个后台。
- 后台仅监听 `127.0.0.1`，与现有行情桥、日志接收器分离。多图表共享同一后台，不重复写库。
- 行情回调不等待网络请求或模型推理；关闭工作台不停止 ATAS 行情采集。
- 第一片验收先证明图表入口、后台与页面可用，再加入模型服务和交易日志。

### 模型服务

- 第一版明确实现 Chat Completions 兼容的文本协议，不承诺兼容任意供应商或模型。
- Base URL、模型名可自填；保留 provider adapter 边界，以后可加 Responses 或其它协议。
- Key 默认只在本次后台会话使用；用户可选择保存至 macOS Keychain。
- Key 不回显、不进入 URL、命令行参数、日志、SQLite、ATAS 工作区或 Git。
- Key 绑定其服务地址；更换地址必须重新填写或确认对应凭据，不自动携带到新主机。
- 远程服务要求 HTTPS；本机模型服务可使用明确配置的 loopback HTTP。禁用跨主机重定向。
- 连接测试、开始分析和后续提问由用户主动触发。没有 Key 时使用明确标记的本地演示，不能假称模型调用成功。
- 模型超时、认证失败、限流、额度错误和无效响应分别显示；不无限重试可能计费的请求。
- 模型没有交易、执行代码、写原始日志或直接修改规则的工具。

### 行情与交易证据

- 行情只经固定 GET 路由读取现有本机桥。分析前核对 `hostMode`、`readOnly`、模拟账户和 freshness。
- 第一版只允许当前 BTC Crypto Sim 场景；真实账户或无法验证账户类型时停止新数据分析。
- 默认摘要包含最近 20 根已闭合 K 线、最近 2 根 Footprint 的前 20 档、每侧 15 档 DOM，
  以及 200 根 Profile 的前 20 个价位。未闭合 K 线单独标识，不混入闭合统计。
- 采用有版本的证据包，记录各端点时间、请求参数、图表聚合单位、质量标记及失败项。
- 总请求上下文设大小上限；截断时明确显示截断范围，不把静默截断的数据当完整数据。
- CVD 明确标注返回窗口及第一次会话重置位置；DOM 只代表可见快照。
- 交易日志作为可选只读适配器接入已有 BTC Orderflow Lab。公共 fork 不复制私有日志、配置或凭据。
  未安装日志组件的用户仍可用行情分析，界面明确显示“交易日志未连接”。
- 通过现有日志 MCP 的 stdio 协议调用固定的只读工具；安装时设置组件路径和数据库路径，
  页面不能提交任意可执行文件或 shell 命令。缺少组件时不自行创建或覆盖用户的交易库。
- 日志适配器只复用现有查询／计算契约。禁止重新猜算手续费、原始风险或逐笔极值。
- 交易复盘只读取用户选定交易的有限上下文。入场判断与事后走势分开，报告保留质量缺口。

### 系统、Prompt、报告

- 系统档案字段：名称、主要周期、交易 setup、入场、退出、风险规则、练习目标。
- Prompt 三层：固定证据与执行边界、用户系统／目标及可编辑指令、本次不可变证据包。
- 系统和 Prompt 每次保存生成新版本。旧报告始终引用当时版本，不被新规则覆盖。
- 默认报告：数据质量 → 可核对事实 → 规则符合／偏离／无法判断 → 待验证假设 → 下一轮练习。
- 模型输出按纯文本或受限 Markdown 呈现，不执行 HTML、脚本、工具调用或指令。
- 报告证据引用必须存在于本次证据包；无效引用标记为无法验证，不能伪装成已核实事实。
- 追问保留同一证据包，明确标识不是新的实时行情；需要更新数据时由用户生成新的分析。
- 第一版使用本地 SQLite 保存配置元数据、版本和报告；不写入原始成交库，不存 Key。

## 本地访问和数据发送边界

- 页面资源和 API 来自同一 loopback origin；后台校验 Host／Origin，拒绝外站跨域调用。
- 用短期本地启动凭证建立会话，凭证不放 URL 查询参数；移除启动片段后再渲染页面。
- 修改配置或开始分析需要有效会话与 CSRF 防护，不能仅凭 localhost 就接受请求。
- 本地页面不加载第三方脚本、字体或分析埋点。
- 发送预览完整列出服务目标及将发送的交易／行情摘要。测试使用合成数据，真实模型费用和数据发送由用户操作。
- 日志只记录错误类别、请求标识和状态，不记录 Key、完整提示词、原始请求或财务数据。

## 实现顺序与验收

1. 图表入口 + 本机工作台 + 连接状态：真实 ATAS 点击可打开页面，重复点击不重复后台；
   无连接或过期数据给出明确状态；既有桥和日志采集保持运行。
2. 模型设置 + 会话 Key／Keychain + 合成数据分析：端点校验、凭据隔离、错误处理、无自动收费重试。
3. 系统／Prompt 版本 + 有证据的行情分析：预览、模型响应、报告持久化、追问与证据引用。
4. 可选日志适配器 + 单笔已平仓复盘：复用现有日志计算，正确处理无费用、数据缺口和无初始风险。
5. AI 规则修改提案 + 接受生成新版本：原报告不被改写，用户可以拒绝提案。
6. 完整回归、实际浏览器交互、ATAS 入口验证、文档与 GitHub 提交。真实付费模型未由用户配置时，
   只报告协议模拟测试已通过，不宣称已完成真实供应商调用验收。

不在本版实现：自动下单、平仓后自动调用、定时云端分析、团队账户、订阅收费、Windows UI 打包、
迁移原始交易账本、全日逐笔行情存储、单 DLL 内嵌全部界面。

## 依据

- 本仓库 `docs/macos.md`：现有运行验收与数据边界。
- 本机 ATAS SDK 与上一阶段类型检查；当前安装目录含 Avalonia 程序集，但这不证明有公开插件窗口 API。
- ATAS 官方 `custom-modules` 文档：模块绘制和输入接口及控件限制。
  https://docs.atas.net/en/modules/custom-modules.html
- ATAS 官方 `PlatformModule`：8.0.15 尚未包含该 API 的版本提示（2026-11-09 实际读取核对）。
  https://docs.atas.net/api/ATAS.Indicators.Modules.PlatformModule.html
- ATAS 官方 `keyboard-mouse`：指标鼠标点击处理。
  https://docs.atas.net/en/chart-indicators/keyboard-mouse.html
- OpenAI 官方 Chat Completions API：选定兼容协议的请求与响应结构；文档也推荐新 OpenAI 专用项目考虑 Responses。
  https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create

补充核验：本机已有 SDK 元数据包含 `ProcessMouseClick`、`ProcessMouseDown`、
`ProcessMouseUp` 与 `GetCursor`。因此图表按钮有实际接口依据，但新按钮仍须运行验收。
